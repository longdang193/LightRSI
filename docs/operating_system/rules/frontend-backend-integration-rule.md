# Frontend-Backend Integration Rule

- Final specifications own approved behavior. Prototypes provide validation evidence. Canonical schemas own transport contracts. Source and tests own implemented behavior. Runtime evidence proves deployed behavior.
- Colocated `*.integration.md` sidecars own temporary contract-to-UI mapping, unresolved mismatches, and acceptance evidence only. Reference schemas; never copy them.
- Deliver cross-boundary work as smallest valuable vertical capability, not isolated frontend and backend phases.
- Prove material backend behavior directly whether or not frontend exists. Frontend, browser, or consumer evidence extends backend proof; it never substitutes for it.
- Use `skill-full-stack-integration` when work crosses UI behavior and backend contracts or routes. Use `skill-backend-verification` for direct backend evidence.
- Use external documentation capability only when active executor exposes it for current version-specific external-library documentation not answered by pinned local sources. Treat result as advisory and resolve it through `docs/operating_system/tooling/runtime-tool-resolution.md`.
- Tool unavailability never blocks safe source-first work and never justifies duplicate contracts, schemas, or documentation.

Operational routing: `docs/operating_system/tooling/frontend-backend-integration-tools.md`.
